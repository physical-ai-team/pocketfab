# C4 Visualizer — 담당: 김세광

C3의 판정 결과를 원본 프레임에 그리고, 과자를 추적해 **검사선 통과 시 1회** 집계한 뒤 C1으로 보낸다.
스펙: [docs/api-spec.md](../docs/api-spec.md) 4장 ③④, 4.2

> ⚠️ **C4는 복제하지 않는다.** 추적 상태가 이 프로세스 메모리에 있어서, 여러 개로 늘리면 같은 과자의 프레임이 흩어져 집계가 틀어진다.

## 파일
| 파일 | 내용 |
|---|---|
| `app/tracker.py` | 과자 단위 집계: 추적 → 검사선 1회 집계 → 다수결 판정. **완성됨** |
| `app/draw.py` | 프레임에 결과 그리기. **완성됨** (아래 "화면 표시") |
| `app/main.py` | 서버 (C3에서 받아 추적·그리기 후 C1으로 전달). 추적 기록(`TRACK_LOG_DIR`)도 여기서 남긴다 |
| `tests/test_tracker.py` | 집계 테스트: 처리 fps 1~3, SAM 2 속도(4.5초 간격), 순서 뒤바뀜, 다수결, 불량 유형, 화면 끝 과자 (`pytest`) |
| `tests/test_draw.py` | 그리기 테스트: 판정 색, 라벨 글자, 화면 끝 과자, 검사선 강조 (`pytest`) |
| `tests/test_tracking_log.py` | 추적 기록 형식 테스트 |

## 집계가 시뮬레이터보다 적을 때 (추적 기록 분석)
1. `.env`에 `TRACK_LOG_DIR=/data/tracking`을 넣고 `docker compose up -d` → 폰 테스트
2. `python tools/analyze_tracking.py` (가장 최근 세션의 `data/tracking/<세션>.jsonl`을 읽는다)
   - **줄별 집계**: 한 줄이 "위·아래 끝 100%, 집계 0개"면 그 줄이 폰 화면 위·아래에 걸려 잘린 것이다. 구도를 넓힌다.
     잘린 과자는 모양이 잘려 `cut`으로 판정되므로 세지 않는 것이 맞다 (규칙은 그대로 둔다).
   - **못 센 과자**: "검사선을 넘기 전에 사라짐"이 많으면 추적이 끊긴 것, "넘은 뒤에 처음 잡힘"이 많으면 C2가 앞 프레임에서
     놓쳤거나 너무 빨리 움직인 것이다 (시뮬레이터 속도를 낮춘다).
   - **표 수**: 중간값이 3 미만이거나 동점이 많으면 속도를 낮춘다.
   - **줄별 판정 사유**: 한 줄만 불량 비율이 크게 높으면 그 줄이 촬영(기울기·반사) 때문에 오판되는 것이다.
     기록에는 지표(원형도·solidity·원 채움률·오목 깊이·`defect_reasons`)와 C4가 그린 결과 이미지
     (`data/tracking/<세션>/<frame_id>.jpg`)도 남으므로 직접 열어 확인한다.
4. 폰이 보낸 원본도 `<frame_id>_orig.jpg`로 남는다. C2·C3를 고친 뒤 `tools/rerun_frames.py`로 이 원본에
   C2 → C3를 다시 돌리면, 폰 테스트 없이 실제 촬영 사진으로 줄별 불량 비율이 어떻게 바뀌는지 볼 수 있다.
3. `--replay`: 폰 없이 기록만으로 추적기를 다시 돌린다. `--max-age`, `--edge-margin`, `--lr-edge-only`로 설정을 바꿔 결과를 비교할 수 있다.

## 화면 표시
- **윤곽선**: `objects[].polygon` (없으면 박스). 불량 빨강(안쪽 반투명 칠) / 정상 초록 / 판단불가 노랑 / 화면 끝(`truncated`) 회색
- **라벨**: 시연 화면(640px)에서는 과자가 지름 40~50px로 촘촘해서, 글자는 불량·판단불가에만 짧게 쓴다.
  - 정상: 글자 없음 (초록 윤곽선만)
  - 불량: `bite` / `D0.13` — 추정 유형(`defect_type`)과 판정을 가른 지표 하나(`defect_reasons` 중 D 오목 깊이 > F 원 채움률 > C 원형도 > S solidity 순)
  - 판단불가: `?` / `m0.42` (마스크 점수)
  - 화면 끝 과자: 회색 윤곽선만 (판정을 믿을 수 없음)
  - 약자 설명은 화면 맨 위 줄에 있다. 추적 번호는 화면에 쓰지 않는다.
- **검사선 통과**(`tracking.counted`): 그 프레임에서 검사선이 판정 색으로 굵어지고, 집계된 과자에 굵은 박스와 `+1 DEFECT`가 뜬다.
  SAM 2는 CPU에서 1fps 미만이라 강조는 결과 프레임 1장에만 나온다.
