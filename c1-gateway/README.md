# C1 Gateway — 담당: 이기태

스마트폰 카메라 페이지, QR 접속, 결과 대시보드, 프레임 유입 제어(백프레셔)를 맡는다.
스펙: [docs/api-spec.md](../docs/api-spec.md) 3장, 4장 ①④, 5장

## 파일
| 파일 | 내용 |
|---|---|
| `app/main.py` | 서버. 카메라 WebSocket 수신 → C2 전송, C4 결과 수신 → 대시보드 중계 |
| `app/static/camera.html` | 스마트폰 카메라 페이지 (`/camera`) |
| `app/static/dashboard.html` | 대시보드 (`/`) |

## 카메라 페이지 (`/camera`)
- 후면 카메라가 기본이다. 한 번 시작하면 카메라 목록이 채워져서, 중지 후 다른 카메라를 고를 수 있다
  (브라우저는 카메라 권한을 받은 뒤에야 카메라 이름을 알려준다).
- 해상도는 보내는 JPEG의 가로 크기다(640 권장 / 960 / 1280). FPS와 함께 중지 상태에서만 바꿀 수 있다.
- 폰을 돌려 영상의 가로·세로가 바뀌어도 매 프레임 종횡비를 유지한 채 보낸다.
- 지원하는 브라우저에서는 스트리밍 중 폰 화면이 꺼지지 않게 한다(Screen Wake Lock). 지원하지 않으면 그냥 넘어간다.

## 대시보드 (`/`)
- 맨 위에 **과자 단위 누적 집계**(검사 통과 / 정상 / 불량 / 판단불가 / 불량률)를 크게 보여준다. 줌 화면 공유에서도 읽히게 하려는 것이다.
  값은 C4의 `tracking.totals`이고, 불량이 새로 집계되면 불량 칸이 잠깐 붉게 깜빡인다.
- **최근 불량**: 검사선을 넘은 불량 과자(`tracking.counted`)를 그 프레임의 `objects[]`와 `track_id`로 맞춰
  불량 유형(`bite`/`cut`/`wedge`/`half`)과 프레임 썸네일을 최근 8개까지 남기고, 유형별 개수를 센다.
  대시보드를 연 뒤부터 세고, 새 카메라 세션이 오면 비운다(C4 누적 집계도 세션마다 0부터 시작).
- **처리 fps 그래프**: 최근 60초, 5초 평균. CPU(SAM 2)에서는 1fps 안팎이라 1초 값은 0과 1을 오가기 때문이다.
- **현재 프레임**: 과자별 판정·불량 유형·네 지표(C 원형도, S solidity, F 원 채움률, D 오목 깊이). 화면 끝에 걸친 과자는 "집계 제외"로 표시한다.
- `main.py`가 C4 결과에서 이 화면에 필요한 필드(`defect_type`, `track_id`, `truncated`, `concavity` 등)만 골라 보낸다 (api-spec 5.1).

## 어디부터 채우면 되나
1. **`camera.html`** — 실제 폰(안드로이드/아이폰)에서 카메라 선택·해상도·화면 켜짐 유지가 되는지 확인한다.
2. **`dashboard.html`** — 시연 리허설 때 줌 공유 화면에서 글자 크기와 배치가 괜찮은지 확인한다.
3. **`main.py`** — 지금은 잘 동작하므로 크게 건드릴 필요 없다. `MAX_IN_FLIGHT`는 C3 복제본 수에서 자동으로 정해진다
   (대시보드의 "처리 중 / 한도", "C3 복제본"에서 확인). 직접 정하려면 `.env`에 값을 넣는다.

## 혼자 확인하기
```powershell
docker compose up --build
python tools/fake_camera.py      # 폰 없이 합성 영상 전송
```
`https://localhost/` 대시보드에 `fake N` 프레임이 보이면 정상이다.
